# PLATE sourced recipe search

Return useful recipes that exist online and remain traceable to their original publisher.

## Inspect first

- `server/Recipe.Api/Services/AzureGroundedRecipeClient.cs`, `EdamamRecipeClient.cs`, `RecipeCatalogService.cs`, `RecipeRankingService.cs`, `RecipeSafetyValidator.cs`, and `RecipeSearchCache.cs`
- `server/Recipe.Api/Models/RecipeModels.cs` and `Options/RecipeCatalogOptions.cs`
- `client/src/App.jsx`, `RecipeHeroImage.jsx`, `recipePhotos.js`, and `recipeArtwork.js`
- `README.md` before changing provider or cache behavior

## Non-negotiable rules

1. Use Azure Responses API with forced `web_search` by default, or the explicitly configured Edamam catalogue. Azure may structure source metadata, but must not create or complete the canonical recipe. When provider directions are unavailable, Azure may add a separate AI cooking guide only when the API and UI explicitly label it as non-canonical and AI-generated.
2. For Azure, accept a recipe only when its exact valid HTTPS publisher URL appears in the response's actual web-search sources or citation annotations. Never trust a URL merely because the model wrote it in JSON. For Edamam, require its valid HTTPS source URL. When credentials, search, citations, the provider, or safe results are unavailable, return a clear error without substitution.
3. Preserve publisher attribution and link to the source for the canonical method. Mark directions as `Provider` only when a licensed provider actually returns them; mark Azure-created guidance as `AiGenerated`; otherwise mark directions `Unavailable`.
4. Apply deterministic allergen, diet, and avoid-list validation after the provider response.
5. Normalize common ingredient variants, exclude ordinary pantry basics from missing counts, and calculate available/missing structured ingredients. When available, put the best cited traditional dish requiring one to three missing non-staple ingredients first and the best no-missing recipe second. Randomize the remainder and move recently shown choices later. When neither preferred category exists, choose the fewest-missing safe result first.
6. In production, never trust an image URL or license claim generated by a model or found in an ordinary web result. Resolve dish photos separately through Wikimedia Commons image-info metadata. Accept only HTTPS bitmap files with an explicit CC0, Public Domain, CC BY, or CC BY-SA license; require a creator and Creative Commons license URL for attribution licenses. Return the image URL, file-description source URL, license type, license URL, and attribution requirements together. If any required value or dish-name match cannot be verified, clear every image field and use recipe-derived fallback artwork. An explicit `AllowUnverifiedForTesting` flag may permit a relevant Commons bitmap only when `IHostEnvironment.IsDevelopment()` is also true; mark it `UnverifiedTestOnly` and show a conspicuous UI warning. Never allow that fallback in production. Do not perform the lookup or mount a remote image when photo display is disabled.
7. Display at most six validated recipes. Request them from Azure in JSON batches of no more than three, combine distinct cited results, and retain earlier validated batches if an optional later batch fails. Make the first ranked result the Top Pick and keep available and missing ingredients visible on cards and details. Never fabricate extra results to reach six.
8. Administrator-editable recipe guidance may tune recommendation style and ranking, but it must never replace or weaken forced web search, citation verification, safety validation, anti-fabrication rules, or the response contract. Protect prompt changes with server-side authorization, persist them outside the client bundle, and never expose the admin secret to ordinary API responses.

## Cache boundary

Cache keys must include the active provider, active prompt revision, normalized ingredients, allergens, avoided ingredients, recent result IDs, diet, time, and servings. Keep full-result caching disabled unless the active provider/search contract explicitly permits every retained field and serving model. `ProviderPermissionConfirmed` is mandatory; never bypass it to improve performance.

## Verify

Test forced web search, rejection of uncited model URLs, provider mapping, safety filtering, halal wine suppression, normalized matching, ranking, commercial-image license allowlisting, attribution completeness, photo fallback behavior, cache isolation between providers, photo preferences, and safety settings, and provider failure paths.
